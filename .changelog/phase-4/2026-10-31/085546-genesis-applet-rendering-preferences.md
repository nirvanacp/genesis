# Per-applet rendering preferences

- Goal: Let the user resolve WebView rendering compatibility problems for any applet through Genesis, without hard-coded applet selectors or changes to other applets' preferences.
- Changes: Added device-local preferences keyed by stable applet ID and an Applet options → Rendering chooser. Default preserves the existing emulator software workaround. Hardware acceleration restores normal WebView rendering; Software compatibility explicitly requests software rendering. Changes apply immediately to matching live and retained applet views and are read when future views are created. Independent external readers keep their existing renderer.
- Decisions: The agent initially proposed an opt-in manifest setting for X. The user explicitly requested a host UI control available to any applet instead. No manifest, SDK or Rust protocol expansion is necessary. The control uses a host-local event and does not discard drafts, cookies or library data. Only X will receive an explicit preference during this task.
- Verification: Android debug assembly and lint passed (zero errors; existing warnings remain). The active X view's software layer was confirmed through a temporary Java debugger. Switching to hardware corrected live glyphs, compose geometry and video painting; the chooser retained X's setting across package updates and process/emulator restarts. Other applet preferences were not changed. No permanent test files were added. The user requested separate commits at significant verified steps.
