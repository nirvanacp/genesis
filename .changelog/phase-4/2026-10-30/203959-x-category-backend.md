# X categorized bookmark backend

- Goal: Store category saves independently from X bookmarks with server-enforced relationships and reliable write reconciliation.
- Changes: Added the Node HTTP/HTTPS service, SQLite schema, validated snapshots/category operations, full-library search, bounded pagination, membership lookup and durable operation receipts. Declared the separate X service. Credentials/database paths come from the existing private provisioning workflow; the expected account is operator configuration.
- Decisions: Follow the approved personal-library authorization model. The bearer credential authorizes the library; a visible X handle only prevents accidental account mixing. Category deletion requires emptiness. Retain snapshots on membership changes, normalize category uniqueness and keep mutation receipts indefinitely. Clarified the snapshot contract to retain at most eight safe visible links within the aggregate 32 KiB bound, because the planned library preserves ordinary links.
- Verification: Syntax and applet checks passed. Disposable in-memory checks passed for normalization, limits, atomic conflicts, independent membership moves/removal, literal full-library search, pagination/stale cursors and same-operation replay. Authenticated HTTP health/API, malformed input and receipt replay passed with a temporary database/token. No test files, password persistence or upstream X mutations.
