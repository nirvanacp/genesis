# Android Studio run recovery

- Goal: Restore reliable Run from Android Studio without clearing Genesis data.
- Changes: Enabled Always install with package manager in the local app run configuration. Restarted Studio to release a stalled deployment. Increased the existing Medium Phone API 37 AVD CPU allocation from one to four, retaining its configured RAM, disk and app data. Backed up the original AVD configuration beside config.ini. Set graphics to host GPU and cold boot after automatic graphics selected SwiftShader and the quick-boot snapshot failed.
- Decisions: Investigation found successful Gradle builds followed by incomplete cold boot and stalled APK installation. A direct standard install also stalled. The one-core guest reported load above 50; the four-core restart initially reported load below four. No AGP/dependency upgrade, app-data wipe or source-code workaround was warranted. Settings are local machine configuration outside tracked source.
- Verification: Android Studio completed deployment after recovery in 27.698 seconds, then a repeat Run installed successfully in 3.837 seconds. The Genesis process ran and its two-app launcher appeared. Android System UI showed a startup ANR and was restarted through its dialog. Final screenshot confirmed the clean two-app launcher; opening Hacker News rendered its live feed and five-section shell. Studio remains open with the app running. Local configuration changes are not portable repository changes; no application source or user data changed. Preserve the pre-existing untracked architecture document.
