# X private Categories architecture

## Phase-4 product direction

The user requires two complete everyday applets, Hacker News and one X client. Internal browser contexts, source routes, Categories, backend services and reader pages do not create additional apps. Preserve stable applet IDs and data. The [controlling improvement plan](../.plans/phase-4/2026-10-30/214048-genesis-two-complete-applets-plan.md) defines the corrective work and acceptance. The current HN-only bundle and X debug qualification described below are implementation status, not the final product. HN functionality is the preservation baseline; X requires integrated end-to-end qualification.

Phase-4 implementation lives in `factory/applets/x.com`. X is installed through the development package workflow; only HN is selected by `genesis.packages.json`. Authenticated emulator journeys and category writes were qualified on 31 October; production distribution and physical-device qualification remain separate. See the [current audit and limits](../.reports/phase-4/2026-10-31/083700-x-ui-audit-and-verification.md).

The user's 31 October correction supersedes the earlier plan's custom Me hub and duplicated Saved mode row. Five stable manifest sections now show Home, Explore, Notifications, Saved and Profile. Profile opens the actual signed-in profile. Categories joins the source Bookmarks/Likes tab row and uses those same destinations on its owned page. Runtime API 2 patterns adapt daily source routes, while auth/settings/chat/paid routes retain ordinary source presentation. Source effects preserve X typography, header spacers and content columns, hide only the redundant primary navigation, add a Home Messages action and per-post category controls. The source owns social actions, media, drafts and ordinary bookmarks. Folder controls never click X's bookmark action. See the [current audit](../.reports/phase-4/2026-10-31/083700-x-ui-audit-and-verification.md).

`extract-post.ts` takes bounded text snapshots from an article's own permalink, avoiding quoted-post identity. `post-controls.ts` binds managed watchers to post IDs and batches membership lookups. `account.ts` reads the desktop signed-in profile link or the bootstrap session's own user entity validated against mobile account controls, never the viewed author. Packaged-page entry uses a one-use host-local ticket and a visible source round trip; it cannot inspect another view's DOM. This handle check prevents accidental account mixing, not hostile impersonation.

`library.tsx` owns category-filtered server search, pagination, captured-post display, category management and safe live-post links. `repository.ts` persists operation IDs before writes, keeps retry payloads only in memory, and reconciles uncertain responses through operation status. Host storage contains preferences, tickets and pending metadata; it is not the category authority and contains no X password/cookie.

The separately hosted Node 24/SQLite backend authenticates a personal library with its independently provisioned bearer token. It enforces normalized category uniqueness, empty-only deletion, 50 categories, 10 memberships per post, canonical decimal post IDs, bounded snapshots, literal substring search, cursor revision checks and atomic receipt-backed mutations. No backend modules or secrets enter frontend bundles. Production hosting/backups and multi-user authorization remain outside this implementation.

The public SDK/services boundary supplies all browser-side capabilities. Rust and Android implement generic route, lifecycle, section, picker, shell and service contracts without X entities. [The operating guide](../.docs/phase-4/2026-10-30/210800-genesis-x-development-guide.md) describes build/import/service setup and the release gate.


## Adaptive folder implementation status

The qualified English post-save Add to Folder action now captures its exact post and permits X to determine native availability. A correlated navigation to `/i/verified-get-verified` or `/i/premium_sign_up` uses a bounded host return, then revalidates the account and opens Applet categories. Known denial routes subsequent folder intents in that active context to the custom editor. Ambiguous toast association, unsupported labels and older hosts retain source recovery and the explicit Categories entry. Native-capable actions remain source-owned; actual Premium picker markup and other folder-management entry points remain unqualified.

Account loading is distinct from confirmed logout. Returned intents wait for account readiness and preserve epoch validation. Controller deadlines release abandoned intents; managed modal dismissal completes ownership. Native Back closes the sheet before leaving the source. X's qualified scroll-faded compose/toast containers receive a narrow opacity correction while hidden/exit values remain source-owned. Shared diagnostics inspect composed ancestry without altering website UI.

Emulator verification passed: real Bookmark → Add to Folder → automatic Home return → custom editor; backend membership write and library read-back; custom removal; native Saved/Categories/Back; final opaque sheet and toast.
