# Build a Genesis applet

Read [factory instructions](../../AGENTS.md), [rules](../../guides/rules.md), [defaults](../../guides/defaults.md), [records](../../guides/applet-records.md) and [native feel](../../guides/native-feel.md). Read the other guides as each step needs them; the [kit README](../../README.md#read-this-first) lists them by need.

1. Resolve the website's canonical `https://` origin and inspect its mobile pages, account pages, forms, loading and failure states. List its website features (attachments, media, downloads, sharing, links to apps, dialogs, permission prompts, sign-in windows) and choose each one's handling from [website features](../../guides/website-features.md). Do not submit anything while inspecting.
2. Run `genesis-applet create <name> --origin <origin> --name "<Product name>"`, where `<name>` is a short product name for the applet, never the website's domain; it becomes the directory and the applet id. `--name` is the name the user sees; without it the manifest takes the website's host name. The default `--template react` gives a React UI; `--template vanilla` gives TypeScript without a framework. To use another framework or an existing project, set `build.foreground` to its `command` and output `dir` as [frameworks](../../guides/frameworks.md) describes. Write the product brief, journeys and design reference in `.specs/current.md`. Ask only about unresolved choices that change the app. Copy the [UI kit](../../guides/ui-kit.md) into `src/` and set its tokens to the product's look before writing any screen.
3. Declare origins and contexts (at most three) in `applet.json`. Declare routes in `src/routes.ts` and pass them to `createRouter`, with overlay screens in `screens`. Follow each journey on the device signed in and signed out and route every URL it lands on ([route every landing URL](../../guides/navigation.md#route-every-landing-url)). Route only the pages the applet customizes; sign-in and other pages without a route show as the website in the same session. A composer the user asked for gets a route and an applet screen.
4. Read each routed page with a JSON read specification, or with a reader in the page module (`src/page.ts`, named by `build.page`) when the page needs code. Give each route a `ready` read with positive evidence, give list records stable unique keys, and give list readers extents for every node a read touches. Give the account reader positive signed-out evidence on every signed-out page variant. Build each screen with all of its [states](../../guides/native-feel.md#screen-states) and its own destination-shaped skeleton from the kit, open details with `navigate({ url })`, and wire every control to its [feedback](../../guides/native-feel.md#taps-and-actions): pressed state, optimistic toggles, minimum busy time, toasts with Undo. Add inputs and desired-state commands with evidence, and storage or a service for applet data. Build each website feature with its recipe from [website features](../../guides/website-features.md), never by sending the user to the website, and fill the spec's Website features table.
5. Run `npm run check` and `npm run build`, install with `genesis-applet dev install`, and walk the journeys, the presentation scenarios and the [native feel scenarios](../../guides/verification.md#native-feel-scenarios) on the device. Mark the acceptance bar in the current spec. Maintain service start commands but start services only when the user asks.
6. Update the current spec, decisions, README and a change record, and commit. Report unmet journeys as failed, blocked or deferred.

## Publishing

Publish only when the user asks for a release. Follow [publishing](../../guides/publishing.md): raise the version with `npm version <patch|minor|major> --no-git-tag-version`, run `genesis-applet publish` and `publish --verify`, commit `published/` with the version change, then run `genesis-applet release`. Never push the tag, never move or reuse one, and never change a published applet's id; tell the user to push.
