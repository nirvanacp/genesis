# Build a Genesis applet

Read [factory instructions](../../AGENTS.md), [rules](../../guides/rules.md), [defaults](../../guides/defaults.md), [records](../../guides/applet-records.md) and the applet's current specs. Use [product scope](../../guides/product-scope.md), [isolation](../../guides/isolated-applets.md), [SDK reference](../../guides/sdk-reference.md), [navigation](../../guides/navigation.md), [interactions](../../guides/interactions.md), [design](../../guides/design.md), [patterns](../../guides/patterns.md), [services/data](../../guides/services-and-data.md) and [verification](../../guides/verification.md) for the affected components.

1. Accept the domain/base URL and desired changes. Inspect canonical HTTPS destination, actual mobile flows, routes, forms and account boundaries with available authorized tools. Preserve explicit deep links/query context. Do not submit consequential actions while inspecting.
2. Create/read current specs, derive connected daily journeys and classify requirements/defaults/practices. Choose ordinary details. Ask only material unresolved choices; retain blocked authenticated flows. Recognize shared all-applet intent and update corresponding authorized guidance.
3. Use matching creator/SDK/host versions. Map manifest routes to hidden adapters, validated models, owned screens and explicit website actions. Add native shell/top-right Genesis options unless overridden; scaffold omission is not a delivery default. Apply mobile visual tokens, skeletons and meaningful controls.
4. Implement source/UI/data components in dependency order, preserving stable identity and data authority. Use public APIs and managed cleanup. Maintain start.sh and port declarations, but start services only on explicit request.
5. Verify real requested launcher/source/UI/data/return journeys and adjacent failures. Update current specs, decisions, README and logical changelog before component commits. Report blocked requirements as unfinished.
